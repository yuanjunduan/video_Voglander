# Voglander 本地全栈服务启动清单

> 用途：一眼看清「整套系统到底要起几个东西、各自用什么脚本/命令起、起完怎么验」。
> 细节（配置对齐、端到端实录、故障排查）见 [`doc/LOCAL-STACK-RUNBOOK.md`](./LOCAL-STACK-RUNBOOK.md)。
> 本文只写**启动方式**，不代替你执行。

---

## 一、结论：只需要 3 个进程 + 2 个远程依赖

| # | 服务 | 端口 | 进程 | 必需 | 一句话启动方式 |
|---|---|---|---|---|---|
| 1 | MySQL | 3306 | 远程 `192.168.118.229` | ✅ | 不在本机，只需确认连通 |
| 2 | Redis | 6380 | 远程 `192.168.118.229` | ✅ | 不在本机，只需确认连通 |
| 3 | voglander 后端 | 8181（+SIP 5060/5061） | `java` / `ApplicationWeb` | ✅ | IDEA Run，或 `mvn -pl voglander-web spring-boot:run`，或 `java -jar voglander.jar` |
| 4 | ZLMediaKit 媒体面 | 8082（+554/1935/10000/8000/443） | `MediaServer.exe` | ✅ | `powershell -ExecutionPolicy Bypass -File .\scripts\zlm-start.ps1` |
| 5 | vben 前端 | 5666 | `node`（vite dev） | ✅ | `pnpm dev:antd` |
| 6 | starter demo | 8081 | `java` | ❌ 可选 | 仅自测 zlm starter 时用 |

**不需要单独启动的东西**（常见误解）：

| 你可能以为要起 | 实际情况 |
|---|---|
| 外部 SIP 服务 / SIP 代理 | 不需要。SIP 服务端 5060、客户端 5061 由 `sip-gateway` starter 在 voglander 的**同一个 JVM 内**绑定 |
| `Sip-Proxy-master`、`go2rtc-master` | 本套环境未使用，不要起 |
| ffmpeg | 不需要常驻。协议验证台推流 / ZLM 转封装时由后端按需拉起子进程 |
| MySQL / Redis（本机） | 本机没有实例，数据源与缓存都指向远程 `192.168.118.229` |
| 播放器（jessibuca / flv.js） | 前端静态资源，随前端 dev server 一起提供，无独立服务 |
| Nginx / 网关 | 前端 vite dev 直接把 `/api` 代理到 8181，无需反向代理 |

**当前状态（2026-10-27 实测）**：8181 ✅ 在听、5666 ✅ 在听、远程 3306/6380 ✅ 可达、**8082/554/1935 ❌ 无监听且无 `MediaServer` 进程**。
→ 也就是说，你接下来**只需要启动 ZLMediaKit**（第 4 项）。

## 二、启动顺序（有硬性依赖，别打乱）

```
① 远程 MySQL / Redis 可达
② voglander 后端 8181        ← 必须早于 ZLM
③ ZLMediaKit 8082
④ vben 前端 5666
⑤（可选）starter demo 8081
```

**为什么后端必须早于 ZLM**：ZLM 启动瞬间会回调 `on_server_started`，后端靠这次回调把节点写进 `tb_media_node`（带 `host`、`secret`）。
若 ZLM 先起、回调打空，之后只有每 10s 的 `on_server_keepalive`，会用 `host=null` 建出一行"僵尸节点"，`host` 永久为 null → 播放取地址必然失败。
补救：`delete from tb_media_node where server_id='zlm-dev';` 后重启 ZLM。

> 你现在后端与前端已在跑，顺序天然满足，直接起 ZLM 即可。

## 三、逐个服务的启动方式

### 0. 外部依赖：MySQL + Redis（远程，只需确认连通）

```powershell
Test-NetConnection 192.168.118.229 -Port 3306 -InformationLevel Quiet
Test-NetConnection 192.168.118.229 -Port 6380 -InformationLevel Quiet
# 两个都应返回 True
```

- 配置位置：`voglander-repository/src/main/resources/application-repo.yml`（数据源、`spring.data.redis`、`spring.cache.type: redis`）。
- 连不上就是外部机器/网络问题，本地没有可替代的启动脚本；退回 SQLite 单机模式才是不依赖 MySQL 的兜底路径。

### 1. voglander 后端 8181（唯一启动入口：`ApplicationWeb`）

启动类：`io.github.lunasaw.voglander.web.ApplicationWeb`（其余模块都是依赖库，不能单独启动）
默认 profile：`prod,repo,inte`；端口：`application.yml → server.port: 8181`。

**方式 A：IDEA（推荐日常开发）**
Run Configuration → Application → Main class = `ApplicationWeb`，**Working directory 设为项目根 `D:\2026_git\voglander-master`**。
（IDEA 运行不执行 Maven resource copy，改过 yml 要 Rebuild 或手动同步 `target/classes`。）

**方式 B：Maven（必须显式指定工作目录）**

```powershell
$env:JAVA_HOME='C:\soft\jdk17'      # 必须 JDK17，JDK25 会让 Lombok 静默失效
cd D:\2026_git\voglander-master
# 首次：先把各模块装进本地仓库（跳过 GPG 签名，本地无 gpg）
mvn -s settings.xml -DskipTests "-Dgpg.skip=true" "-Dmaven.javadoc.skip=true" install
# 启动
mvn -s settings.xml -B -pl voglander-web spring-boot:run "-Dspring-boot.run.workingDirectory=D:\2026_git\voglander-master"
```

> `-Dspring-boot.run.workingDirectory` 不能省：协议验证台的 `media-file` 是相对**项目根**的路径，而 `spring-boot:run` 默认工作目录是**模块目录**，会把路径拼成 `…\voglander-web\voglander-web\…`，导致"文件校验失败"、自动推流静默失败、`live/start` 报 700001 超时。

**方式 C：fat jar（改过配置必须重新 package，jar 内打的是构建时的 yml）**

```powershell
java -jar voglander-web\target\voglander.jar --spring.profiles.active=prod,repo,inte
```

**启动成功判据**

```powershell
Invoke-RestMethod http://127.0.0.1:8181/api/v1/health
# {"code":0,"data":{"status":"UP","components":{"db":{"status":"UP"},"redis-A":{"status":"UP"},"zlm":{"status":"UP","circuit_state":"CLOSED"}}}}
Get-NetUDPEndpoint -LocalPort 5060,5061 | Select-Object LocalAddress,LocalPort
```

> `zlm` 字段只是 Resilience4j **熔断器状态**，**不能**当作 ZLM 在线判据（ZLM 没起时这里也可能是 CLOSED）。

### 2. ZLMediaKit 8082（← 当前唯一缺失的服务）

| 项 | 值 |
|---|---|
| 运行时目录 | `D:\2026_git\shipin\ZLMediaKit`（`MediaServer.exe` + `config.ini` + `www` + `default.pem` + `log\console.log`） |
| 启动脚本 | `D:\2026_git\voglander-master\scripts\zlm-start.ps1` |
| 脚本做什么 | 幂等对齐 `config.ini`（`mediaServerId=zlm-dev` / `http.port=8082` / hook 全部指向 `127.0.0.1:8181` / ffmpeg `C:/soft/ffmpeg-7.0.2/bin/ffmpeg.exe`）→ 用 `Win32_Process.Create` **脱离 shell** 启动 → REST 自检 → 查 `tb_media_node` |
| 前置 | 后端 8181 已在监听（脚本会探测并提示） |

```powershell
cd D:\2026_git\voglander-master
powershell -ExecutionPolicy Bypass -File .\scripts\zlm-start.ps1

# 可选参数（默认值即本机基线）：
#   -Root D:\2026_git\shipin\ZLMediaKit  -HttpPort 8082  -Secret zlm  -MediaServerId zlm-dev  -BackendPort 8181
```

**手动启（不用脚本时）**：

```powershell
cd D:\2026_git\shipin\ZLMediaKit
cmd /c "MediaServer.exe > log\console.log 2>&1"      # 或用 cmd 窗口直接双击运行 MediaServer.exe
```

> 坑：**不要用 PowerShell `Start-Process` 起**，会话结束时子进程会被回收（进程消失、8082 不监听，但节点可能已注册）。脚本用 `Win32_Process.Create` 才真正脱离。

**启动成功判据**

```powershell
Invoke-RestMethod "http://127.0.0.1:8082/index/api/getServerConfig?secret=zlm"
# data[0]: general.mediaServerId=zlm-dev / http.port=8082 / hook.enable=1
#          hook.on_server_started=http://127.0.0.1:8181/index/hook/on_server_started
Get-Content D:\2026_git\shipin\ZLMediaKit\log\console.log -Tail 20
```

后端日志（`%USERPROFILE%\logs\voglander\voglander-info.log`）应出现：

```
onServerStarted::param = ...
处理服务器启动回调成功，节点ID: zlm-dev, 完整地址: http://127.0.0.1:8082
```

## 四、全部起完后的自检（按顺序粘贴）

```powershell
# 1) 端口全通：8181 后端 / 5666 前端 / 8082 ZLM REST / 554 RTSP / 1935 RTMP
foreach ($p in 8181,5666,8082,554,1935) {
  "$p => " + [bool](Test-NetConnection 127.0.0.1 -Port $p -InformationLevel Quiet -WarningAction SilentlyContinue)
}
# 2) SIP 端口在进程内绑定
Get-NetUDPEndpoint -LocalPort 5060,5061 | Select-Object LocalAddress,LocalPort,OwningProcess
# 3) 后端健康
Invoke-RestMethod http://127.0.0.1:8181/api/v1/health
# 4) ZLM 配置基线
Invoke-RestMethod "http://127.0.0.1:8082/index/api/getServerConfig?secret=zlm"
# 5) 媒体节点已入库且心跳在变新（期望 1 行：zlm-dev / http://127.0.0.1:8082 / status=1）
python -c "import pymysql;c=pymysql.connect(host='192.168.118.229',port=3306,user='root',password='<见本地配置>',database='voglander',charset='utf8mb4');cur=c.cursor();cur.execute('select server_id,host,secret,status,enabled,keepalive from tb_media_node');print(cur.fetchall());c.close()"
# 6) 前端 → 后端代理
Invoke-RestMethod http://127.0.0.1:5666/api/api/v1/health
```

判定口径：**1~6 全绿 = 全栈就绪**。第 5 步 `host` 必须是 `http://127.0.0.1:8082` 而不是 NULL，否则播放取地址会失败。

## 五、停止与重启

```powershell
# ZLM
Stop-Process -Name MediaServer -Force
# 后端：IDEA 里 Stop，或按端口找进程
Get-NetTCPConnection -LocalPort 8181 -State Listen | Select-Object OwningProcess
Stop-Process -Id <PID> -Force
# 前端：在其控制台 Ctrl+C，或
Get-NetTCPConnection -LocalPort 5666 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

- 本机没有 Windows 版一键重启脚本；仓库根的 `restart.sh` 是 **bash**（`lsof`/`setsid`/`nohup`），只适用于 Linux/macOS，Windows 下请按上面的命令手工执行。
- `live/stop` 后流不会立刻消失：`refCount` 归零只打 `pending_close` 标记（`PENDING_CLOSE_SEC=90`），由 `LiveSessionGcService`（60s tick）执行真实 BYE。等 60~90s，或 `Stop-Process -Name ffmpeg` 强断。

## 七、常见启动失败速查

| 现象 | 根因 | 处理 |
|---|---|---|
| ZLM 起来后进程立刻消失、8082 不监听 | 用 `Start-Process` 起，子进程被会话回收 | 用 `scripts\zlm-start.ps1` |
| 前端播放失败、`tb_media_node.host` 为 NULL | ZLM 早于后端启动，节点被 keepalive 用空 host 建出来 | `delete from tb_media_node where server_id='zlm-dev';` 后重启 ZLM |
| `/api/v1/health` 里 `zlm` 显示非 UP，但 8082 明明通 | 那是熔断器状态，不是在线状态 | 以 8082 REST + `tb_media_node` 为准 |
| 后端编译大量"找不到符号"（Lombok 失效） | 用了 JDK 25 | `$env:JAVA_HOME='C:\soft\jdk17'` |
| `live/start` 报 `文件校验失败 … 当前工作目录 …\voglander-web` | `mvn -pl voglander-web spring-boot:run` 工作目录是模块目录 | 加 `-Dspring-boot.run.workingDirectory=D:\2026_git\voglander-master` |
| `live/start` 报 700001 拉流超时 | `voglander.protocol-lab.push.ffmpeg-path` 是 `/usr/bin/ffmpeg` | 改成 `C:/soft/ffmpeg-7.0.2/bin/ffmpeg.exe` 后重启后端 |
| 报 `Cannot find cache named 'device'` | `spring.cache.type: redis` 丢了，或 `gateway.gb28181.store.type=redis` 抢了连接工厂 | 恢复 `cache.type: redis`；单机保持 `store.type: memory` |
| `.ps1` 报一堆"数组索引表达式丢失/缺少终止符" | PowerShell 5.1 读无 BOM 的 UTF-8 中文脚本 | 脚本保持纯 ASCII，或存成 UTF-8 **带 BOM** |
| 浏览器 `/api/v1/health` 报 `No static resource v1/health` | 漏了 baseURL 的 `/api` 层 | 用 `/api/api/v1/health` |
| `POST /api/v1/auth/login` 404 | `AuthController` 映射是 `/auth`，**没有** `/api/v1` 前缀 | 打 `/auth/login` |
